# FPGA Drum Machine — Project Plan
# Tang Nano 9K / GW1NR-9C / OSS CAD Suite

## Goal
A standalone hardware drum machine and synthesizer running entirely on the FPGA.
No CPU, no software audio engine — all sound is generated by digital logic in Verilog.
UART lets a laptop control notes, sounds, and sequences.
HDMI provides a visual display of the sequencer state.

## Steps

### ✅ Step 1 — LED blink
**What:** Blink LED0 at 1 Hz.
**Why:** Proves the full toolchain works end-to-end.
**Concepts:** Synchronous logic, flip-flops, `always @(posedge clk)`, active-low I/O.

---

### ✅ Step 2 — Button input
**What:** S1 increments a counter displayed in binary on all 6 LEDs. S2 resets.
**Why:** Establishes the input model you'll use everywhere.
**Concepts:** Debounce, edge detection, `s_prev & ~s_clean`.

---

### Step 3 — Parameterized clock divider
**What:** A reusable module `divider #(.N(X))` that toggles an output every N clock
cycles, producing a square wave at 27_000_000 / (2*N) Hz. Test it by driving each
LED at a different blink rate from the same module instantiated six times.
**Why:** Every frequency you ever generate — audio tones, BPM clock, UART baud rate —
is clock division. Build it once, reuse it everywhere.
**Concepts:** Module parameters (`parameter`, `localparam`), module instantiation,
multiple instances of the same module with different parameters.

---

### Step 4 — Square-wave audio (one note)
**What:** Toggle a GPIO pin at 440 Hz (A4). Wire the pin through a 100Ω resistor
and 10µF capacitor to a 3.5mm jack. You should hear a tone.
**Why:** First audio output. Proves the hardware path works.
**Concepts:** Frequency calculation (27_000_000 / (2 * 440) ≈ 30_681 cycles),
the RC low-pass filter as a DAC approximation.
**Hardware:** Uncomment `audio_out` in `constraints/tangnano9k.cst`.
Choose any free header pin (e.g. pin 25). Wire: GPIO → 100Ω → cap+ → jack tip.
                                                                     cap– → GND.
**Note:** PWM is noisy but audible. It carries you through step 5.
After step 5 switch to the I2S DAC for clean audio.

---

### Step 5 — Multiple musical notes
**What:** Seven buttons / UART bytes select seven notes (a major scale).
Pressing S1 cycles through them; the tone changes in real time.
**Why:** Multiple simultaneous clock dividers, note lookup table.
**Concepts:** `case` statements, ROM-style parameter arrays, note-to-divisor lookup.
**Key calculation:** divisor = 27_000_000 / (2 * frequency)
  C4 = 261.6 Hz → 51,603   E4 = 329.6 Hz → 40,954
  D4 = 293.7 Hz → 45,958   F4 = 349.2 Hz → 38,659 ... etc.

---

### Step 6 — DDS synthesizer (sine wave)
**What:** Direct Digital Synthesis. A phase accumulator adds a tuning word every clock
cycle; the top bits address a 256-entry sine lookup table stored in block RAM;
the output goes to the I2S DAC.
**Why:** Square waves are harsh. DDS gives you sine, triangle, sawtooth — the
foundation of all the drum sounds coming in step 8.
**Concepts:** Fixed-point arithmetic, phase accumulator, block RAM (BRAM),
I2S serial protocol, the DDS equation: tuning_word = (freq * 2^32) / clk_freq.
**Hardware:** Wire the I2S DAC (PCM5102A): BCK, LRCK, DATA to three GPIO pins.
  BCK  = bit clock  (pin 26)
  LRCK = word clock (pin 27)  — toggles at sample rate (e.g. 48 kHz)
  DATA = serial audio data (pin 28)

---

### Step 7 — UART control from laptop
**What:** A UART receiver that reads bytes from the laptop over USB-C (via the
on-board CH552). Protocol: one byte selects a note (e.g. MIDI note number);
the synthesizer plays it immediately.
**Why:** Makes the system controllable in real time without touching the board.
Sets up the control channel needed for the sequencer.
**Concepts:** UART framing (start bit, 8 data bits, stop bit), shift register RX,
baud rate clock generation (115200 baud → divisor = 27_000_000 / 115200 ≈ 234),
oversampling (sample in the middle of each bit).
**No extra hardware:** the CH552 already bridges USB-C to UART pins 17/18.
Test with: `screen /dev/tty.usbserial-1400 115200` or `minicom`.

---

### Step 8 — Drum synthesis
**What:** Three drum voices synthesized entirely in logic:
  - **Kick:** exponentially decaying sine wave (~60 Hz). A counter-based envelope
    multiplies the DDS amplitude down to zero over ~200 ms.
  - **Snare:** noise burst mixed with a mid-frequency tone (~200 Hz).
    Noise from a linear-feedback shift register (LFSR).
  - **Hi-hat:** high-frequency filtered noise (LFSR + IIR high-shelf).
Triggered by UART bytes (e.g. 'k', 's', 'h').
**Why:** This is the core of the drum machine.
**Concepts:** LFSR (pseudo-random noise), amplitude envelope (attack/decay),
fixed-point multiply for envelope scaling, voice mixing (add + saturate).

---

### Step 9 — 16-step sequencer
**What:** A 16-step grid. Each step holds a bitmask of which voices fire (kick,
snare, hi-hat, plus a melodic note). A BPM clock advances the step pointer.
UART writes individual steps (e.g. `S<step><mask>`) and sets BPM.
LEDs show the current step position.
**Why:** Turns the instrument into a drum machine.
**Concepts:** FSM (idle / playing / recording), block RAM for pattern storage,
BPM-to-divisor calculation (BPM / 60 / 4 for 16th notes), UART command parser.

---

### Step 10 — HDMI display
**What:** 640×480 @ 60 Hz HDMI output showing the sequencer grid:
16 columns (steps), one row per voice, current-step highlight,
note name and BPM displayed as text.
**Why:** Completes the instrument. Closes the project.
**Concepts:** VGA timing (hsync, vsync, blanking intervals), TMDS encoding,
rPLL (to generate 25.175 MHz pixel clock from 27 MHz),
ELVDS_OBUF primitives for differential output,
font ROM for character rendering.
**Note:** This is the only step where Gowin EDA might be useful (for the PLL
wizard). The open-source flow supports rPLL and ELVDS; you will configure them
by reading the Apicula primitive docs rather than using a GUI.
